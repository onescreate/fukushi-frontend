# Phase 2 実装計画 — 通所予定・打刻

> 作成日: 2026-07-03 / 前提: Phase 1 完了（マスタ・認証・キオスクPIN認証）
> 進め方: 各ステップごとに確認しながら実装。1ステップ完了→動作確認→次へ。

## このPhaseのゴール

「**利用者の通所予定を登録・申請・承認でき、タブレットで通所/退所を打刻し、遅刻・早退・欠席を把握できる**」状態。あわせて、利用者が**自宅から予定を確認・申請できる個人ページ**の入口を作る。

対応する要件（①通所予定管理）:
- スケジュール登録（出席日・時間・中抜け）
- 通所・退所打刻
- 遅刻・早退・欠席の報告と管理
- 個々のデータ把握（当日の利用者一覧など）

---

## ステップ分割

### Step 2-0｜データモデル追加（マイグレーション）
- `schedules`（予定: 日付・予定IN/OUT・状態・承認情報）
- `schedule_details`（中抜け等: 外出/戻り時刻）
- `attendances`（実績: 実IN/OUT・遅刻/早退/欠席の判定結果・欠席理由）
- Prisma マイグレーションで追加（既存テーブルはそのまま）。

### Step 2-1｜予定の登録・一覧（管理側）
- 管理画面で、利用者ごとの通所予定を登録・編集・削除（カレンダー/一覧）。
- バック: schedules CRUD（テナント/権限制御）。

### Step 2-2｜変更申請と承認フロー
- 利用者（または代理でスタッフ）が予定の追加・変更を**申請**。
- 管理者が**承認/却下**。承認待ち件数をバッジ表示。
- 業務ルール（要確認）: 翌月分は当月15日までの申請なら自動承認、それ以降は承認待ち 等。

### Step 2-3｜打刻の実運用（キオスク拡張）
- Phase 1 のPIN認証の先に、**通所打刻／退所打刻**を追加。
- 打刻を `attendances` に記録し、予定と比較して**遅刻・早退**を判定。
- 業務ルール（要確認）: 遅刻/早退の判定基準（予定時刻＋猶予何分か）、二重打刻の扱い。

### Step 2-4｜当日ロースター＋遅刻早退欠席の管理
- 「今日の利用者」一覧（予定・打刻状況・遅刻/早退/欠席）を管理画面に表示。
- 欠席の記録・理由入力、打刻漏れの手動補正。
- 業務ルール（要確認）: 欠席の確定タイミング、事前欠席連絡の扱い。

### Step 2-5｜中抜け（外出・戻り）の記録
- タブレットまたは管理画面で、中抜けの外出/戻りを記録。

### Step 2-6｜個人ページ（利用者の自宅ログイン）
- 利用者が `loginId＋パスワード` でログインする**個人用画面**（管理画面とは別レイアウト）。
- 自分の予定の確認、変更申請、履歴閲覧。
- ※ 範囲が大きいので、Step 2-2 の申請を管理側で先に作り、個人ページは後半で追加も可。

## この Phase で決める必要がある業務ルール（該当ステップ直前に確認）

1. **予定の自動承認**（2-2）: 「翌月分は当月15日まで自動承認、それ以降は承認待ち」で確定か。締め日は施設共通か店舗ごとか。
2. **遅刻の判定**（2-3）: 予定開始時刻を何分過ぎたら遅刻か（猶予）。
3. **早退の判定**（2-3）: 予定終了より前の退所を早退とするか。
4. **欠席の扱い**（2-4）: 打刻がない予定日を欠席とするか。確定タイミング（当日終了時/締め時）と事前欠席連絡。
5. **中抜け**（2-5）: 記録項目（外出・戻り時刻、理由）と、勤務時間からの控除方法。
6. **二重打刻・打刻可能時間**（2-3）: 同日に複数回打刻した場合の扱い。
7. **個人ページの範囲**（2-6）: 今フェーズで作るか、まず管理側だけにするか。
