# Phase 3 実装計画 — 食事管理

> 作成日: 2026-07-03 / 前提: Phase 2 完了（通所・打刻）
> 進め方: 各ステップごとに確認しながら実装。旧仕様（legacy-v0）を踏襲。DBはマイグレーションのみ・ローカル適用は私／本番はユーザー。

## このPhaseのゴール（要件②食事管理）

- 食事の予約（必要な日／変更／取消。**締切あり**）
- 予約していた場合の**喫食入力**
- **食事料金の請求・管理**（料金・キャンセル料・消費税・適格請求書・入金）
- 食事の注文・納品管理

打刻画面の「食事」枠も、このPhaseで中身が入る。

## 旧仕様のポイント（踏襲対象・着手時に legacy-v0 で再確認）
- 食事: `meal_date` 単位、状態＝予約/キャンセル/取消/喫食済、金額 `amount`
- **15時締め**（当日15時以降は変更不可の判定に使用）
- **キャンセル料**: 利用日の**14日前以降**のキャンセルは cancel_fee 課金、それ以前は無料取消
- 料金は**履歴型**（`price_histories`: meal_fee / cancel_fee / effective_date）。利用者個別 `special_meal_fee` を優先
- 消費税は**履歴型設定**（標準/軽減、内税/外税、端数）※Phase設計で決定済みの方針
- 適格請求書情報（`invoice_settings`）、納品数（`meal_deliveries`）

## ステップ分割

### Step 3-0｜データモデル追加（マイグレーション）
- `meals`（食事予約: user×日付、状態、金額、situation）
- `price_histories`（食事料金・キャンセル料の履歴）
- `tax_settings`（消費税: 税率/内税外税/端数/区分・履歴型）
- `invoice_settings`（適格請求書情報・履歴型）
- `meal_deliveries`（発注数・納品数）
- `billing_records`（月次請求）
- ※ 一度に全部ではなく、各ステップで必要な分を追加してもよい。

### Step 3-1｜料金・税・請求書の設定（マスタ）
- 食事料金／キャンセル料（店舗ごと・適用開始日つき履歴）
- 消費税設定（税率・内税/外税・端数・軽減/標準）
- 適格請求書情報（登録番号・住所・振込先 等）

### Step 3-2｜食事予約（管理側＋個人ページ）
- 月カレンダーで必要な日を予約・変更・取消
- 15時締め・14日キャンセル料ルールの適用
- 利用者本人も個人ページから予約できる

### Step 3-3｜喫食入力
- 予約分の「喫食済み」記録（管理側／打刻画面と連動）

### Step 3-4｜食事料金の請求・入金管理
- 月次で食事料金＋キャンセル料＋消費税を算出
- 請求書の発行（PDF・適格請求書対応）
- 入金状況の管理

### Step 3-5｜食事の注文・納品管理
- 予約数（発注数）と実納品数の差分管理

## この Phase で確定する業務ルール（該当ステップ直前に確認）
1. **食事の締切**: 「当日15時」で固定か、店舗ごとに設定にするか。
2. **キャンセル料**: 「14日前以降は課金」で確定か。金額は設定（cancel_fee）。
3. **食事料金**: 既定額、利用者個別料金の扱い。
4. **消費税**: 食事は軽減8%か標準10%か／内税・外税／端数処理。
5. **適格請求書**: インボイス対応の要否・記載項目・PDFレイアウト。
6. **予約主体**: 利用者本人の予約可否（旧仕様は可）。
